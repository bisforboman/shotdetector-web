# One page for everything: a timeline, cards, a module per panel (2026-10-25)

The backlog adds about ten things to the page: shot statistics, a score graph, a waveform, the reference tone and
sound measures, bitrate and keyframes, the file's description, warnings, thumbnails. Each row was written on its own
and puts its panel somewhere different ("under the player", "on the shots strip", "a sound panel"). Each also edits
`app.js`, `Api.cs` and `worker.js`, so the rows can only run one at a time. The page's first design is in
[2026-10-24-the-page.md](2026-10-24-the-page.md) ("The page itself"); this widens it.

## Where each panel goes

### Question

How does one page show all of it at once without becoming a pile of widgets?

### Choices

1. **One timeline under the video, plus cards.** Everything that happens over time is a lane of one timeline,
   under the `<video>`: the shots, the scores, the waveform, bitrate and keyframes, silences and the tone's span. The
   lanes share one time axis and one playhead that follows `timeupdate`, and a click on any lane seeks the video.
   What isn't over time is a card beside it: the file's description, the shot statistics, the sound numbers,
   warnings. The shots table stays below. At phone width the cards stack under the timeline.
2. **Each row places its own panel**, as the rows say today.

### Answer

**1.** One axis means a cut, a loud moment and a bitrate spike line up by eye, which is the point of showing them
together. A row adds a lane or a card; it doesn't design a layout.

## How the code lets rows run side by side

### Question

`app.js`, `Api.cs` and `worker.js` are one file each. How do several rows work on the page at the same time?

### Choices

1. **A module per panel, still no build step.** `app.js` keeps the page's states and wires the panels in.
   `timeline.js` owns the axis, the playhead, seeking and lane registration. Each panel is a native ES module of its
   own (`panels/<name>.js`), loaded with `<script type="module">`, and adds itself as a lane or a card. `Api` becomes
   partial class files, one per feature (`Api.cs` for open and detect, `Api.Audio.cs`, and so on). `worker.js` calls
   any export by name (`{ type: 'call', name, args }`), so a new export needs no edit there.
2. **Keep one file each** and run the rows one at a time.

### Answer

**1.** A row then touches its own module, its own partial file and a line or two that list it. The backlog's status
lines are the only shared text left. No bundler, no framework: a visitor still reads the page's source as it is.
