# H.264 in AVI (2026-11-13)

Backlog "H.264 in AVI". `AviInput` refuses any AVI video but MJPEG (`Refusal.AviCodec`); ManagedCodecs 0.11.0 decodes
H.264 in AVI (an Annex B stream, frames timed by the packets' decoding-order times as FFmpeg's, seeking by 'idx1'
keyframes). One thing the row doesn't settle: B-frames.

Measured on 2026-11-13 on the ManagedCodecs 0.13.0 bump's branch (`ccr-d0d88369-sh5umk`: ShotDetector 3.30.0,
FrameReader 2.26.0, ManagedCodecs 0.13.0) with FFmpeg 8.1.3 (BtbN's shared build the checks pin): `testsrc2`,
`mandelbrot` and `smptehdbars` cut together at 320x240 and 25 fps (as make-samples.sh's `three`), `-c:v libx264` into
AVI with its default B-frames and with `-bf 0`; `AviInput` let through H.264 (the SPS read from the first packet's
Annex B NAL units, `H264Decoder` for the frames) and NativeCheck run on both; ShotDetector's source (main) read for
how its file path times such frames.

## What FFmpeg says about such a file

| Field | FFmpeg | Where the core gets it |
| --- | --- | --- |
| `time_base`, `avg_frame_rate` | the video `strh`'s `dwScale/dwRate` (1/25, 1001/30000) and its inverse | as for MJPEG: `AviDemuxer`'s `TimeBase` |
| `nb_frames`, duration | `dwLength`; the format's duration as for MJPEG (4.560000, 4.004000) | `AviHeader`, as for MJPEG |
| `start_pts` | 0 (the first packet's dts) | the first packet's pts |
| `pix_fmt`, colour tags, chroma location | the SPS's: `yuv420p`, unknown colours, `left` (no VUI colour) | `SpsInfo` of the SPS in the first packet (in-band: there is no `avcC`), as `Mp4Input`'s |
| field order | the parser's: `progressive` | `H264Decoder.FieldOrder`, as `Mp4Input`'s |
| packets | dts 0, 1, 2, ...; **pts N/A** on every packet, B-frames or not | ManagedCodecs gives pts = dts |
| frames | **pts N/A**; `best_effort_timestamp` and `pkt_dts` the dts of the packet the reorder depth later (`has_b_frames`: 0 without B-frames, 2 with libx264's): 2, 3, ..., 113, then N/A for the last two | ManagedCodecs: 2, 3, ..., 115 (the last two extrapolated) |

ShotDetector's file path (`VideoReader`, `InProcessProbe.FrameTimestamp`) takes a file whose packets have no pts as it
takes MPEG-PS: each frame labelled as OpenCV labels it, its pts if set and non-zero, else its packet's dts, else 0, in
output order. Without B-frames that is 0, 1, 2, ..., the packets' dts, which is what the core gives already.
With B-frames it is 2, 3, ..., 113, 0, 0: the shots start at 0.080 s and the last frames are labelled at 0.

## What the measurement showed

- **Without B-frames** everything is the FFmpeg path's: every run's scenes and stats CSVs, the shots as JSON and HTML,
  the timelines and chapters; ranges, four decoder threads, a split run, a stop half-way, resumes, corrections and the
  frame types against ffprobe. What differed is the description and the checks' own reading of FFmpeg: the field order
  (`Unknown`, to be the decoder's `Progressive`), NativeCheck's oracle (FrameReader's `FramePts` is null on every frame:
  it must take OpenCV's rule above), its packet check (ffprobe's packets have no pts), and `DamagedCheck`'s ffprobe
  frame pts (N/A).
- **With B-frames** the scenes CSV was the FFmpeg path's (the frames given at the decoder's times, 2 to 115), the stats
  CSV not: the file path's last two frames are at 0, so its rows end at frame 114 and start with a frame compared with
  itself. `YuvVideo` can't say the file path's times: `Detect(YuvVideo, ...)` refuses them ("YuvVideo.FrameTimestamps
  must rise from each frame to the next (presentation order): entry 112 is 0, after 113"). That is ShotDetector's to
  settle (its `YuvVideo` taking a file's labels without pts, or its file path labelling such frames otherwise), not
  something to work around here.

## Question: B-frames

**A. Without B-frames now, B-frames upstream (recommended).** `AviInput` takes H.264 whose frames come in decoding
order (the first frame's time is the first packet's: no reorder delay) and refuses one with B-frames, saying so; the
sample isolating it is libx264 with `-bf 0`. B-frames become a Waiting row on a ShotDetector question (how a file's
frames without pts are labelled, and `YuvVideo` saying it), asked of the shotdetector coordinator.

**B. Both at once, after ShotDetector.** Ask ShotDetector first; the row waits, H.264 in AVI stays refused until both
are exact.
